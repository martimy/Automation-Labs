# Introduction

This handout is only for students who missed Lab 1, but it is **not** a substitute for Lab 1. The instructions below are intended to create the folder structure and Git repository needed for all labs.

> If any step below fails in a way you cannot resolve in a few minutes, stop and check with your lab instructor rather than guessing. Getting the repository or environment into a bad state now will cause confusing problems in every later lab.

# Step 1: Accept Your Classroom Assignment

1. Open the “Classroom 50” assignment link provided by your instructor and accept it to generate your personal remote repository.
2. Generate a personal access token on GitHub following the steps in the “GitHub Access Token Setup” document. Use this token as your password when prompted during the push process.

# Step 2: Create the Directory Structure

Create a `labs` directory.

```bash
mkdir -p ~/labs && cd ~/labs
```

# Step 3: Initiate Git Repository

1. Initialize the repository and set the main branch name.

  ```bash
  git init
  git branch -m main
  ```

2. Configure your Git identity. Use your own name and email address.

  ```bash
  git config --global user.name "Your Name"
  git config --global user.email "your.dal.email@dal.ca"
  ```

3. Create a global .gitignore file in ~/labs.

  ```bash
  cat > .gitignore << 'EOF'
  # your Python virtual environment
  .velab/
  # Python bytecode
  __pycache__/
  # sensitive token files used in later labs
  .env
  # directories auto-generated by Containerlab
  **/clab-*/
  EOF
  ```

# Step 4: Create the Shared Python Virtual Environment

1. Create and activate a Python virtual environment.

  ```bash
  cd ~/labs
  python3 -m venv .velab
  source .velab/bin/activate
  ```

Your prompt should now be prefixed with `(.velab)`. Leave it active, or reactivate it with the same `source` command whenever you return to a new terminal session.

# Step 5: Make The First Commit

1. Run `git status` and observe that `.gitignore` and `requirements.txt` are listed as untracked, while `.velab` is not showing.

    ```bash
    git status
    ```

2. Stage your work for the first commit.

    ```bash
    git add .gitignore requirements.txt
    ```

3. Verify the change in status. The files should now be listed as changes to be committed.

    ```bash
    git status
    ```

4. Perform your initial commit.

    ```bash
    git commit -m "Initial commit: Lab 2 catch up"
    ```

5. Review your commit history using `git log`.

    ```bash
    git log
    git log --oneline
    ```



# You Are Ready for Lab 2

Proceed to Lab 2 starting at Task 0, exactly as your classmates who completed Lab 1 will. Every path and command in Lab 2 will now work as written.
